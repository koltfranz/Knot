# 结绳 Knot v0.8.1 发布说明

发布日期：2026-09-27　上一版本：v0.8.0

补丁版：**只修缺陷，不新增功能**。三处都是「让人以为哪里坏了、其实只是提示不对或流程一直没跑通」的问题。

## 修复内容

### 1. 目录里没有账本时，提示不再说「请先修复账本」

在没有 `main.knot` 的目录运行 `查` / `余` / `检查` / `图` 等读取类命令，旧版会先报
`main.knot:0:0 错误：文件不存在：main.knot`，再补一句 `错误 1，请先修复账本` ——
看起来像账本坏了，实际只是这里没有账本。现在改为：

```
错误：当前目录没有账本 main.knot；可用 `knot create 我的账本` 新建，
或 `knot 示例` 复制示例账本，或用 `--账本 路径` 指定
```

退出码由 `1`（账本校验失败）改为 `2`（用法错误），与 `打开` / `界面` 一致；
Git pre-commit 等场景仍会正确失败（非 0）。

### 2. Windows 上的 CI 一直红

`scripts/生成语法大全.py`、`scripts/性能基准.py`、`scripts/打包.py`、`scripts/构建可执行.py`
打印中文前没有调用 `setup_console()`：在 stdout 为 `cp1252` 的 Windows 运行器上抛
`UnicodeEncodeError`，导致 CI 的「语法大全一致性」步骤在 Windows 分支一直失败。
现在四个脚本统一先切 UTF-8 控制台。

### 3. Release 的 Nuitka 作业一直红（三平台可执行从未产出）

`scripts/构建可执行.py` 以 `--output-dir 值` 与 `--output-filename 值` 形式传参，
Nuitka 要求 `--output-dir=值` / `--output-filename=值`；因此在 Linux 与 macOS 上直接报
`option requires an argument with '--output-dir='`，在 Windows 上先撞到上面的编码问题。
现已修正参数形式，`v0.8.1` 的 Release 工作流会真正产出三平台可执行程序与 `knot.pyz`。

## 兼容性

- 账本文件、命令参数、配置格式均无变化；`v0.8.0` 可直接升级
- 唯一可见变化：缺少账本时读取类命令的**提示文案与退出码**（`1` → `2`）
- 语法仍为 v0.7.0 冻结状态

## 验收情况

| 项 | 结果 |
|---|---|
| 测试 | 321 项通过（新增「缺少账本提示」回归 1 项） |
| 静态检查 | `ruff check` 与 `ruff format --check` 通过；`scripts/生成语法大全.py --检查` 一致 |

| CI | 全绿：三平台 × Python 3.11/3.13 测试矩阵、zipapp 冒烟、`installers` 双平台真实安装 / 卸载冒烟 |
| Release | Nuitka 三平台可执行 + `knot.pyz`（本版起才真正产出，见修复 3） |

## 已知边界

- 与 v0.8.0 相同：无文件锁与多端冲突检测；PyPI 未发布；Docker 镜像未在本机验证
- Nuitka 可执行程序体积较大且需要目标平台构建（不支持交叉编译），由 CI 在打 tag 时产出

## 升级方式

```bash
git pull                     # 或下载 Release 附件
sh ./安装.sh                 # 重复执行安装脚本即升级（Windows：.\安装.ps1）
knot --version               # 应显示 0.8.1
```
