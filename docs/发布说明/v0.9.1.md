# 结绳 Knot v0.9.1 发布说明

发布日期：2026-09-30　上一版本：v0.9.0

补丁版：修复 **v0.9.0 的桌面入口在 Windows 上「选择窗口能弹出、但每个选项点完都没反应」** 的问题。

## 问题原因

桌面/开始菜单快捷方式用 `pythonw.exe` 启动（为了不弹黑窗）。**pythonw 没有控制台**，
此时 Python 里 `sys.stdin`、`sys.stdout`、`sys.stderr` 全都是 `None`。入口代码里有一句

```python
if sys.stdin.isatty() and sys.stdout.isatty():   # None.isatty() → AttributeError
```

抛出 `AttributeError`；而 pythonw 没有 stderr，异常无处输出、也没有崩溃对话框，
于是表现为**静默失败**：窗口正常弹出，点哪个选项都像是「没反应」。

## 修复内容

- 所有标准流访问改为安全判空（`entry.stream_is_tty()` / `entry.in_terminal()`），
  无控制台环境下按「非终端」处理 —— 即在新窗口里拉起界面，这正是桌面入口的预期行为
- `console_executable()`：`pythonw.exe` 启动时换回同目录的 `python.exe`，
  否则入口拉起的窗口里看不到任何输出，也无法 Ctrl+C 停止服务
- 桌面入口的未预期异常不再静默：Windows 下弹消息框给出失败原因（`entry.report_error`），
  其它平台写 stderr
- 选择窗口的子进程显式 `stdin=DEVNULL` + UTF-8 解码，Windows 下以 `CREATE_NO_WINDOW` 启动，
  既不闪控制台窗口也不受编码影响

## 兼容性

- 只改桌面入口的健壮性：账本格式、命令、参数、安装位置均无变化
- 升级方式：重新运行一次安装脚本即可（`安装.ps1` / `安装.sh`，重复执行即升级），
  桌面快捷方式会指向更新后的版本

## 验收情况

| 项 | 结果 |
|---|---|
| 复现 | 把 `sys.stdin/stdout/stderr` 置为 `None` 后调用入口，旧版稳定抛 `AttributeError: 'NoneType' object has no attribute 'isatty'`（与用户现象一致） |
| 修复验证 | 同一场景下入口返回 0 并在新窗口拉起终端界面；真实 `pythonw.exe -m knot 入口 --界面 终端` 亦验证通过 |
| 测试 | 349 项通过（新增「无控制台」回归测试组 7 项：判空、默认回退、spawn 分发、错误上报、子进程选项、console_executable 选择） |
| 静态检查 | `ruff check` / `ruff format --check` 通过 |

## 已知边界

- 与 v0.9.0 相同（Windows 不再产出 Nuitka 可执行，改用 `knot.pyz` 或安装器；选择窗口依赖系统工具）
- 入口的浏览器/终端两种打开方式依赖系统能创建新窗口（Windows 控制台、macOS Terminal、Linux 终端模拟器）

## 升级方式

```powershell
powershell -ExecutionPolicy Bypass -File .\安装.ps1     # Windows（重复安装即升级）
```
```bash
sh ./安装.sh                                           # macOS / Linux
```
