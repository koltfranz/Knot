# 账本语法规范（GRAMMAR）

| 项 | 值 |
|---|---|
| 适用版本 | knot ≥ 0.1.0 |
| 状态 | 定稿 |
| 依据 | 《结绳Knot开发文档》第 3 章 |
| 规范用语 | MUST / MUST NOT / SHOULD / SHOULD NOT / MAY 遵循 RFC 2119 |

本文档是结绳系统的唯一数据契约。任何实现与本文档冲突时，以本文档为准；修改本文档 MUST 同步升级其版本并在开发文档变更记录中登记。

## 1 文件与编码

| 项 | 规范 |
|---|---|
| 扩展名 | `.knot` |
| 编码 | 写入 MUST 为 UTF-8；读取 MUST 兼容 BOM（`utf-8-sig`） |
| 行尾 | 兼容 LF / CRLF；写入沿用文件既有行尾风格 |
| 注释 | 以 `;` 起始，可整行或行尾 |
| 缩进 | 分录相对指令行缩进；推荐 2 空格；解析 MUST 探测并沿用文件既有缩进风格 |
| 顺序 | 文本顺序 MUST NOT 影响语义；加载后按 `(日期, 源码行号)` 稳定排序 |

### 1.1 账本目录约定

| 文件 | 作用 |
|---|---|
| `main.knot` | 主账本入口（可用 `--账本` / `--ledger` 覆盖） |
| `别名.knot` | 用户自定义别名（可选，`include` 引入） |
| `规则/分类规则.knot` | 学习式分类规则（可选，`include` 引入） |
| `<年份>.knot` | 年份文件；`记` 命令按交易日期插入对应年份文件 |

`include` MUST 支持相对路径与通配符，且在解析期展开。

## 2 词法

### 2.1 科目名字符类

```python
ACCOUNT_CHARS = (
    r"\u4e00-\u9fff"      # CJK 统一表意文字
    r"\u3400-\u4dbf"      # CJK 扩展 A
    r"\uf900-\ufaff"      # CJK 兼容表意文字
    r"A-Za-z0-9_\-"
)
ACCOUNT_RE = re.compile(f"[{ACCOUNT_CHARS}]+(:[{ACCOUNT_CHARS}]+)*")
```

实现 MUST NOT 使用 `\w` 匹配科目名。完整科目名 SHOULD 为 `根:子科目:…` 形式；单段名称（如 `招行`、`吃饭`）视为输入别名，由别名系统归一化；未声明的科目由校验流水线按 `strict` 宽容度产生提示。

### 2.2 记号表

| 记号 | 形式 | 说明 |
|---|---|---|
| 日期 | `YYYY-MM-DD` | 文件内 MUST 为 ISO 格式；中文日期仅用于命令行输入 |
| 标志 | `*` `!` `?` `P` | 见 4.1 |
| 字符串 | `"..."` | 支持 `\"` 与 `\\` 转义；用于收款方、摘要、周期、事件 |
| 金额 | `-?\d[\d,]*(\.\d+)?` | 千分位逗号可选；解析后为 `Decimal` |
| 币种 / 商品 | `[A-Z][A-Z0-9]{1,7}` | 如 `CNY`、`USD`、`FUND` |
| 科目 | 见 2.1 | |
| 标签 | `#名称` | 名称不含空白 |
| 链接 | `^名称` | 名称不含空白 |
| 元数据 | `; 键: 值` | 位于交易头部或分录之后，归属最近的主体 |
| 成本 | `{单价 币种}` / `@ 单价` / `@@ 总价` | 见 4.3 |
| 对手科目 | `@ 科目` | 见 4.4 |
| 注释 | `; 任意文本` | 不匹配元数据形式时仅作注释 |

## 3 指令全集

| 指令 | 语法 | 说明 |
|---|---|---|
| `option` | `option "键" "值"` | 全局选项；同键多次出现时后者覆盖前者 |
| `include` | `include "路径或通配符"` | 引入其它文件；通配符匹配结果按路径名排序 |
| `open` | `日期 open 科目 [币种…]` | 开立科目 |
| `close` | `日期 close 科目` | 关闭科目 |
| `balance` | `日期 balance 科目 金额` | 余额断言；金额 MUST 带币种或沿用科目默认币种 |
| `price` | `日期 price 商品 金额` | 报价 / 汇率 |
| `commodity` | `日期 commodity 代码` | 商品声明 |
| `recur` | `日期 recur "周期" "说明" from 起 to 止` + 分录 | 定期交易模板，仅在内存实例化 |
| `budget` | `日期 budget 周期 科目 金额` | 预算 |
| `event` | `日期 event "名称" "值"` | 备忘事件 |
| 交易 | 见第 4 章 | |

### 3.1 周期取值

`daily` / `weekly` / `monthly` / `quarterly` / `yearly`，中文别名 `每天` / `每周` / `每月` / `每季度` / `每年`。

## 4 交易

```
日期 [标志] ["收款方"] ["摘要"] [#标签…] [^链接…]
  [; 元数据键: 值]
  科目  [金额] [币种] [{成本}|@单价|@@总价] [@对手科目]
  科目  [金额] [币种] ...
```

- 单个字符串 MUST 解析为摘要（`narration`）；两个字符串 MUST 解析为收款方（`payee`）与摘要
- 标签与链接 MAY 出现在头部任意位置且可多个

### 4.1 标志

| 标志 | 含义 | 用途 |
|---|---|---|
| `*` | 已确认（默认） | 正常交易 |
| `!` | 待确认 | 需复核 |
| `?` | 待分类 | 收件箱，默认归入 `费用:待分类` |
| `P` | 已对账 | 已与账单核对 |

### 4.2 金额写法

| 写法 | 语义 |
|---|---|
| `38.00 CNY` | 显式币种金额 |
| `38.00` | 省略币种，取科目默认币种（默认 `operating_currency`） |
| 留空 | 自动配平腿，由系统计算 |
| `-173.00 CNY` | 负值 |
| `1000 FUND {3.8500 CNY}` | 带成本基础（记账币种单价） |
| `1000 FUND @ 4.10 CNY` | 带成交价（分录内） |
| `1000 FUND @@ 4100.00 CNY` | 带总价 |

金额运算 MUST 全程 `Decimal`；平衡校验 MUST 使用 `abs(合计) < 0.005`。

### 4.3 成本

`{单价 币种}` 表达成本基础；`@ 单价` 与 `@@ 总价` 为分录内成交信息。三者在模型中都归一化为 `Cost(number, currency, kind)`。

### 4.4 对手科目

单腿交易 MUST 使用 `@ 对手科目` 指明对方科目；未指定时取 `default_asset`（费用类）或 `default_income`（收入类）。系统据此生成反向分录并标记 `generated=True`，该生成分录 MUST NOT 写回文件。

多分录交易中，恰有一腿金额留空时由系统补足其相反数；多于一腿留空为错误。

## 5 校验规则

加载后 MUST 依次执行：

1. 展开定期交易（仅内存）
2. 按 `(日期, 源码行号)` 稳定排序
3. 自动开立科目（按 `strict` 宽容度产生提示）
4. 单腿配平与自动配平腿生成
5. 借贷平衡校验：每笔交易全部腿之和 MUST ≈ 0
6. 库存与成本校验
7. 余额断言校验：断言日期（含）之前该科目及子科目合计 MUST ≈ 断言值
8. 会计恒等式校验：全部科目余额之和 MUST ≈ 0

## 6 写回约定

- 写操作 MUST 仅修改受影响的行区间，MUST NOT 全文件重新序列化（`整理` 命令除外）
- 编辑 MUST 按行号降序应用；写入 MUST 为原子操作（临时文件 + `replace`）
- 新增交易 MUST 插入至对应年份文件的日期位置，并保持与其上下块之间恰有一个空行
- 渲染 MUST 沿用文件的既有缩进宽度与列对齐风格
- 未编辑行的字节 MUST 保持不变（由 `test_writer.py` 断言）

## 7 诊断

诊断级别为 `error` / `warning` / `hint`，输出格式：

```
main.knot:42:5  错误：未知科目 "费用:餐引"
  42 |   费用:餐引    38.00 CNY
         ^^^^^^^^
  提示：是否意为 "费用:餐饮"？（相似度 0.75）
```

- 解析 MUST NOT 因单个错误终止；MUST 实现恐慌模式恢复（跳至下一日期行）
- 错误 MUST NOT 抛出异常，MUST 收集至诊断列表
- 每条指令 MUST 记录源码行区间（`src_file` / `src_line_start` / `src_line_end`）
- 纠错建议 SHOULD 使用 `difflib.get_close_matches`
- 显示宽度 MUST 经 `width.py` 计算，MUST NOT 使用 `len()`

## 8 与命令行输入的关系

- 文件内语法固定：中文科目、ISO 日期、半角标点
- 命令行输入 MUST 先经 `normalize_text()`（全角转半角 + NFKC），再进入解析
- 中文数字（`2万3`）、中文日期（`昨天`、`9月20日`）、货币符号（`¥`、`元`、`块`）仅作命令行输入形式，归一化后写入文件
